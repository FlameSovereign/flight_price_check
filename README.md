# flight_price_check · 回国商务舱价格监控 + 买/等预测

每天自动扫一遍 Google Flights，盯住几条“性价比路线”（亚特兰大直接出发、土航经伊斯坦布尔、经东京转机、先飞休斯顿再坐全日空），
把价格攒成时间序列，再用一个小模型回答一个问题：**这个日期的票，现在买，还是再等等？**

最新报告：[`reports/latest.md`](reports/latest.md)

## 为什么第一天就能训练模型

Google Flights 每次搜索的页面里，除了航班列表，还藏着两样东西：

1. 这条航线 / 日期 / 舱位的 **“常见价格区间”**（就是网页上 “Prices are currently typical” 那个判断）；
2. **过去约 60 天的每日最低价**（网页上的价格历史图）。

所以扫一次 ~350 个（策略 × 城市 × 出发日）组合，就直接拿到 ~2 万个“某天的价格 → 之后两周的价格”的样本，
不用先攒几个月数据。之后每天的定时任务再往每条序列后面续一天。

## 监控什么

全在 [`config/watchlist.toml`](config/watchlist.toml) 里，改完就生效（测试用的是 `tests/fixtures/` 里的冻结副本，随便改不会让每日任务挂掉）：

| 策略 | 怎么搜 | 有 60 天历史？ |
|---|---|---|
| `atl-any` | ATL 出发，任意航司 | ✅ |
| `atl-tk` | ATL 出发，只看土耳其航空（经 IST） | ✅ |
| `atl-japan` | ATL 出发，只允许在美国/加拿大枢纽 + 东京转机，结果必须经 NRT/HND | ❌（只有当天价，靠每日累积） |
| `iah-ana` | IAH 出发，只看全日空；另查一张前一天的 ATL→IAH 经济舱当定位航段，计入总价 | ✅ |

目的地默认上海（PVG+SHA）和北京（PEK+PKX），一个城市的多个机场在同一次搜索里覆盖。

**日期和买法**（`[search] trip` 和 `[dates]`）：

- 现在按实际行程设置：**去程 5 月（每 4 天一个日期）、回程 8 月（每 6 天一个）**，`trip = ["round-trip", "two-one-ways"]`，同时追踪两种买法：
  - **一张往返票**：每个去程日期都和每个回程日期配一次（报告里是一张“去程 × 回程”的价格表）；
  - **两张单程**：5 月的去程单程、8 月的回程单程各自追踪，两段各自给买/等建议，可以分开下单。
- 实测（2026-10）：目前在售的打折商务舱往返票，大多最长只能停留约 1 个月——停留 ≤31 天有 12–15 个选择、$4.8k 起，
  ≥33 天基本只剩 $8.5k 以上；5 月去 8 月回的往返票，Google 上暂时一张都没有（单程两边都有）。
  更长停留的便宜往返票往往要等航司放出夏季运价，所以每天盯着、一出现就提醒。
- 不设 `outbound` / `return` 时改用滚动网格：未来 `start_days`–`end_days` 天、每 `step_days` 天一个出发日，回程 = 出发后 `return_after_days` 天。
- 换了设置以后，旧数据还留着给模型学习，报告只显示当前设置的结果。

## 本地运行

需要 [uv](https://docs.astral.sh/uv/)。

```bash
uv sync
uv run flightcheck search ATL PVG,SHA 2026-12-10              # 随手查一次，打印航班和价格历史
uv run flightcheck search ATL PVG,SHA 2026-12-10 --airlines TK
uv run flightcheck collect --limit 20                          # 跑清单里的前 20 个搜索
uv run flightcheck report                                      # 训练模型 + 生成 reports/latest.md
uv run flightcheck run                                         # collect + report
uv run pytest
```

## 每日自动运行

[`.github/workflows/daily.yml`](.github/workflows/daily.yml) 每天亚特兰大时间早上 7 点左右跑一次：
采集 → 训练 → 生成报告 → 把 `data/` 和 `reports/` 提交回仓库。
某张 A 类票跌破 `[alerts]` 里设的提醒价（往返票 `round_trip`，单程 `one_way`），或比上次提醒时更便宜时，会自动开一个 GitHub issue（GitHub 会发邮件/推送给你）。在 `[trip]` 里写了 `committed = true` 之后，改成按“按你的买法”的决策表提醒（见下文）。
已经提醒过的价格记在 `data/alerted.csv`，不会因为某天抓取不完整或重跑而重复提醒。
也可以在 Actions 页面手动点 “Run workflow”。

一次大约 450–500 个请求、20–50 分钟（Google 会稍微限速）；`--max-minutes` 到点就收工，已抓到的数据照样保存、提交。

定时任务只在仓库的**默认分支**上跑。先合并 PR，再把默认分支切到 `main`；顺序反过来的话，`main` 上还没有 workflow 文件，定时任务会悄悄停掉。

## 模型

- **标签**：从某天起 14 天内，最低价会不会再便宜 ≥3%（都可在 `[model]` 里调）。
- **特征**：只用当天及以前的价格：离出发天数、相对 28 天最低/中位/最高、3/7/14 天涨跌、波动率、多久没变价、
  这个出发日比前后相邻日期贵多少、出发月份/星期、策略。
- **模型**：所有航线放一起训练的梯度提升树（scikit-learn `HistGradientBoostingClassifier`）。
- **对照规则**：价格比 28 天最低价贵 5% 以上就等。商务舱价格其实是在几个固定档位之间跳（便宜舱位开/关），
  “最近见过更便宜的价”本身就是“便宜舱位可能再开”的信号。
- **验证**：逐周回放（walk-forward）。最近几周每周一折，每折只用那周之前、标签已完全揭晓的数据训练，
  再把模型和规则都当成下单策略回放，和“立刻买”、事后最优比较平均省了多少。
- **建议列**：跟随过去几周回放里省得最多的策略（模型 / 规则 / 直接买）。离出发不足 21 天一律买。
  模型只有在回放里赢过规则，才会接管建议。

## 按你的买法：每天一句“买 / 等 / 不买”

报告最上面一节，是把过去几次买票的经验写成的规则，每天对照当天的价格给一个动作。
规则从你自己的订票和 Google Flights 价格追踪记录里总结出来，这些原始记录不进仓库。总结出来的规则又用仓库数据和往年公开票价检验过。
代码在 [`playbook.py`](src/flightcheck/playbook.py)，参数在 `config/watchlist.toml` 的 `[trip]` 和 `[playbook]`。

1. **先承诺，再盯价**（`[trip]`）。没写 `committed = true` 之前，报告只写“本来会买”，不提醒。超过封顶价 `cap` 的绝不建议买，到 D-80 改成问你；没定 `cap` 时，D-80 比 `ok` 线贵的走法也先问你。`purchased = true` 后就不再提醒。
2. **只拿 A 类票比目标价**。A1：一张票、一家航司、每程最多转一次。A2：一张票、同一家航司或同一联盟，第一次转机在北美（例如美航+国泰经达拉斯）。长途段航司要在 `allow` 白名单里。其余是 B 类，只作参考。每个搜索会存前 5 个行程，A 类票就算被更便宜的 B 类票挡在后面，也照样算数。
3. **按每个出发日倒推**：D-130 进主窗口；D-95 起不再等旧低价；D-80 兜底，拿同一出发日的“往返”和“两张单程 + 定位 + $150 分票风险（落地和回程不在同一个城市再加 $150 换城市）”比，哪个便宜买哪个；D-63 这个日期出局。所有候选日都出局时，报告直接请你拍板。
4. **一张决策表**（整趟、含定位）：

   | 价格 | D-95 之前 | D-95 起 |
   |---|---|---|
   | ≤ 目标（`[alerts] round_trip`） | 当天买 | 当天买 |
   | ≤ 航司线（`carrier_lines`，土航 $5,500） | 当天买 | 当天买 |
   | ≤ `good` | 在 14 天最低档（3% 以内）就买；7 天内见过更低一档就最多等 7 天 | 买 |
   | ≤ `ok` | 不买 | 比两张单程贵不到 $300 就买 |
   | 更贵 | 不买 | D-80 起买整趟最便宜的走法 |

   价格变动不到 3% 算同一档，不当回事。14 天最低档只看 A 类票的价格，按日历天数算。两张单程只在 D-80 兜底时考虑，例外有两种：两段合计已经低于目标价；或者过了 D-110，回程已经涨了一档，而两段合计 ≤ $5,300。
5. **手查**（`checks_from` 起，每周一、周四）。Google Flights 经常看不到停留超过一个月的便宜往返。报告会列出最值得查的 3 组日期（各不同出发日）和航司官网链接。查到的价记进 `data/manual_quotes.csv`：列是 `date,carrier,depart,ret,city,price,stops,via,source`；`carrier` 写代码，如 `TK`、`AA+CX`；`via` 是第一次转机的机场；价格只写数字。2 天内的报价和 Google 报价按同一张表判断；读不了的行会跳过，并在报告里说明。
6. **买的时候**：在航司官网直接买，付款前看票规里的最长停留、改期费和能不能退。美国出发、提前 ≥7 天订的票，24 小时内可以免费取消或保留，所以“买”的意思是：今天下单，明天再看一眼。
7. **记账**：每天最好的 A 类走法和动作记在 `data/decisions.csv`，明年 2 月用真实的春季数据重新标定这些线。

提醒（GitHub issue）跟着行程状态走：
- 没承诺之前：跌破 `[alerts]` 提醒价的 A 类票提醒你；
- `committed = true` 之后：改成决策表说“买”的票，同一张票价格没变低就不重复提醒；“买”的条件一旦消失又回来，会再提醒一次；
- `purchased = true` 之后：什么都不提醒。

## 远期预测：两张单程能不能凑到 5k？

上面的模型只看两周。报告里的“远期预测”回答的是整件事真正的问题：**5 月去、8 月回的两张单程，加起来能不能压到 `[alerts] round_trip`（$5,000）以内，大概什么时候？**

- 两个模拟器各自用最近 120 天的价格变化，给每段单程模拟 2,000 条未来的每日价格走势，结果取平均：
  - [`markov.py`](src/flightcheck/markov.py)：找处境相似的航线（离 14 天最低价多远、离这条航线常见价多远、最近跳得多不多），照搬它们真实发生过的涨跌；
  - [`regime.py`](src/flightcheck/regime.py)：把票价当成在几个舱位档位之间跳，每天按概率往下跳、往上跳或不动，落点是这条航线最近卖过的价位。
- 输出：每段 30 天后的价格区间；出发前最后几个月的 1 号之前，至少有一天跌到目标价的概率；把 $5,000 分给去程和回程、两段都买到的胜算最大的分法（可以照这两个价设提醒）。
- 怎么选的：先在固定回测上比较了四种方法（还有订票曲线、分位数梯度提升树），并检查有没有偷看未来数据。
  这两个合起来，7/14/30 天的误差比随机游走小 27%/46%/59%，80% 区间实际覆盖 85%/85%/84%。
- **局限要看清**：只验证到 30 天，而且只有两个检验时点。预测 2 月的概率，只是“如果接下来几个月和最近两个月一样”的推演。
  最近两个月票价在涨，这个趋势会被带进去。航司春季放出便宜夏季往返价这种事件，它完全不知道——那种票一出现，每日任务会直接提醒。

## 往年参考：2/3 月买暑假的商务舱往返，都是什么价？

[`reference/past_fares.csv`](reference/past_fares.csv) 收了 156 条有出处的美国⇄中国商务舱票价（2017–2026），每条都附来源链接和原文引用。
来源包括交易博客、论坛、中文羊毛站，以及 Kayak/cheapflights 的历史网页快照。

| 年份 | 1–3 月的数据 | 行情 |
|---|---|---|
| 2018–2019 | 交易博客，票规完整 | 疫情前 1–3 月常有促销，暑假往返 $1,400–2,700；中国航司常限最长停留 3 个月 |
| 2021–2022 | 没有 | 疫情管控：单程就要 $5,000–12,500 |
| 2023 | 只有月均价 | 美国—北京商务往返均价 $10,615，最低约 $5,000–5,900 |
| 2024 | 2 条 | 约 $5,100 起 |
| 2025 | 17 条 | 找到的具体往返 $3,155–6,439；2–3 月均价 $5,063–5,349 |
| 2026 | 27 条 | 5–8 月出发的往返 16 条，$3,444–6,340，14 条低于 $5,000。东海岸单一航司：卡塔尔 $4,495–4,502、大韩 $4,625、日航 $4,722、东航 $5,270 |

- **2025–2026 年，2/3 月买到约 $5,000 的单一航司暑假往返，是正常的公开价**（接近当月均价），不是特价。
  经停的航司（卡塔尔、大韩、日航、土航、菲航）常在 $4,500 以下；直飞（国航 JFK、达美 DTW）约 $6,250–6,450。
- 2021–2026 年没找到专门在 2/3 月的促销；反复出现的促销在 9–12 月（感恩节、黑五）。
- 亚特兰大出发、1–3 月买 5–8 月出发的往返，一条都没找到。ATL 只有 2026 年 3 月临时出发的 $6,250–8,556。
- 5 月去 8 月回（约 3 个月）符合见到的所有票规：2026 年 3.5–6 个月的行程都订得到。2019 年南航限最长 3 个月，得 8 月初前回。
- **Google Flights 不是全部。** Kayak 交易页上见过国泰 ATL⇄北京 2027-04-04 去、05-03 回 $4,841（未核实），而 Google 上只看国泰是 $10,701。
  停留一个月以上的便宜往返，值得直接去航司官网查。

## 局限

- 数据来自 Google Flights 网页（非官方接口，参考了 [fast-flights](https://github.com/AWeirdDev/flights) 对查询格式的逆向）。
  Google 改版可能会让解析失效，测试和每日任务会第一时间报错。
- 价格是 Google 当时找到的最低公布价；不含里程票、不看具体舱位代码，个别结果可能是分开出票的组合。
- 同航线相邻日期价格高度相关，有效样本比表面数字少得多；模型会随着每天的数据积累变准，也可能证明“没法预测”——
  报告里的回测数字会如实告诉你是哪种。
